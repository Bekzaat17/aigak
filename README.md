# aigak

**От ссылки к доказательствам.** Локальный MVP помощника инспектора для анализа возможного игорного контента и подготовки проекта пакета материалов. Казахстан; русский и казахский интерфейс.

Основной сценарий: **ссылка / файл / текст → Анализировать → признаки и источники → уточнения инспектора → ZIP с документами**.

## Что работает в первой версии

- Публичный HTTP(S) URL: сохранение HTTP-ответа, метаданных и редиректов; браузерный снимок и DOM при доступном Chrome/Chromium.
- PNG, JPEG, WebP: локальный OCR на русском, казахском и английском. PDF: текстовый слой и OCR сканированных страниц. TXT/HTML: извлечение текста. Неподдерживаемые файлы сохраняются как оригиналы с явным ограничением.
- Признаки: азартные игры, бонусы, денежные операции, ставки/выигрыши. У каждого — дословная цитата и идентификатор сохранённого источника.
- Продвинутый анализ из трёх этапов через AI Gateway. Цитаты сверяются с сохранённым текстом; при сбое остаются результаты предыдущих этапов и явные ограничения.
- Предварительная оценка вероятности **игорного предложения**, если AI подключён. Это субъективная, не откалиброванная оценка модели, а не вероятность нарушения закона. Без AI процент не рассчитывается.
- Интерактив: подтвердить / отклонить / не уверен, комментарии к признакам, вопросы о происхождении и контексте. Ответы сохраняются в журнале и отчётах.
- Базовый DOCX-шаблон, его скачивание, загрузка собственного шаблона с полями. Шаблон выбирается перед анализом.
- ZIP: документы DOCX на RU/KK, стандартные PDF/HTML-отчёты, оригиналы и производные файлы, JSON дела, журнал, SHA-256-манифест и скрипт проверки. Если браузер недоступен, HTML остаётся пригодным для печати, отсутствие PDF отмечается в README архива.
- История проверок в SQLite; файлы сохраняются локально. Демо явно помечено как синтетическое.

## Быстрый запуск

Нужен Node.js **22.13+** (проверено на Node 26), npm и Chrome либо Chromium для Playwright.

```bash
git clone https://github.com/Bekzaat17/aigak.git
cd aigak
npm ci
cp .env.example .env
npm run setup:ocr
npm run dev
```

Открыть **http://localhost:4317**. Кнопка «Открыть пример» показывает сценарий без AI-ключа и без реального объекта проверки.

В `.env.example` задан `BROWSER_CHANNEL=chrome` для уже установленного Google Chrome. Если Chrome отсутствует:

```bash
npx playwright install chromium
```

После этого удалите `BROWSER_CHANNEL=chrome` из `.env`. Для Linux могут потребоваться системные зависимости браузера (`npx playwright install --with-deps chromium`).

`npm run setup:ocr` однократно скачивает языковые модели rus/kaz/eng. Затем OCR работает локально. Данные находятся в `data/`; каталог, `.env` и тестовые материалы исключены из Git.

### AI

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4.1-mini
```

Перезапустите сервер и выберите «Продвинутая · ИИ» или «Pro · Расследование». Настроенному ИИ-провайдеру отправляется извлечённый текст только выбранной проверки. Ключ не передаётся браузеру. В адаптере Responses используется `store: false`; это не обещание нулевого хранения со стороны провайдера. В первой сессии реальный AI-вызов не проверялся: ключ не был настроен. Контракт и проверка цитат покрыты локальными тестами.

### Сборка и проверки

```bash
npm run build
npm test
npm start
```

`npm start` обслуживает собранный интерфейс. Для изменений серверного TypeScript перезапустите `npm run dev`.

## Собственный шаблон

Откройте настройки шаблона рядом с формой, скачайте базовый DOCX, измените его в Word и загрузите обратно. Ограничение: 2 МБ, без макросов, встроенных объектов и внешних связей. Поля указываются фигурными скобками:

| Поле | Значение |
| --- | --- |
| `{case_number}` | Номер проверки, обязательное поле |
| `{findings}` | Признаки, цитаты, источники и решения инспектора, обязательное поле |
| `{evidence_list}` | Опись и контрольные суммы, обязательное поле |
| `{title}`, `{source_url}`, `{created_at}` | Название, URL и время получения |
| `{assessment}`, `{likelihood}` | Вывод и предварительная оценка AI либо указание её отсутствия |
| `{officer}`, `{notes}` | Инспектор, замечания и ответы на уточняющие вопросы |
| `{review_status}`, `{draft_notice}` | Состояние проверки и отметка проекта |
| `{limitations}` | Ограничения анализа |

Произвольный DOCX без этих полей автоматически не размечается. Язык и оформление заголовков пользовательского шаблона сохраняются; значения подставляются отдельно на RU и KK. Пользовательский шаблон применяется к DOCX, а PDF/HTML имеют стандартное оформление. Документы описывают сохранённые материалы; приложение не создаёт вымышленные доказательства.

## Состав пакета

```text
document-ru.docx / document-kk.docx   Документы по выбранному шаблону
report-ru.pdf / report-kk.pdf         Стандартные отчёты (если доступен браузер)
report-ru.html / report-kk.html       Версии для просмотра и печати
template-source.docx                 Исходный выбранный шаблон
evidence/                            Оригиналы, текст, снимки и метаданные
case.json                            Связи материалов, выводы и решения
audit.json                           Локальный журнал с цепочкой хэшей
manifest.json                        Контрольные суммы файлов
verify.mjs                           Проверка целостности после распаковки
```

Для проверки: `node verify.mjs` из распакованного архива. Манифест сам не подписан внешней доверенной стороной.

## Стек и структура

React 19, TypeScript, Vite, Express 5, SQLite `node:sqlite`, Playwright, Tesseract.js, PDF.js, docx/docxtemplater, JSZip. Шрифты включены в сборку, Google Fonts при открытии интерфейса не вызывается.

```text

server/workflow.ts   Очередь и подтверждение инспектором
server/store.ts      SQLite, сохранение оригиналов и контроль целостности
server/templates.ts  Загрузка, проверка и хранение DOCX-шаблонов

server/rules/        Каталог и движок базовых правил RU/KK

server/network.ts    Проверка адресов и DNS pinning для HTTP
tests/               Тесты целостности, SSRF, цитат, шаблонов и workflow

docs/ROADMAP.md      План продолжения: специализированные агенты и право

```

## Границы первой версии

- **Однопользовательский локальный пилот**, привязан к `127.0.0.1`. Нет авторизации, ролей, общей рабочей среды или готовности к публичному размещению. Не публикуйте сервер напрямую в интернет.
- Браузерные запросы ограничены публичными адресами, GET и бюджетом ресурсов. Сложные сайты, авторизация, CAPTCHA, видео и частично загружаемые страницы могут требовать ручных материалов. В production нужен изолированный браузерный worker и сетевой egress-контроль.
- OCR ошибается, особенно в казахских буквах: сравнивайте цитаты с изображением. PDF: до 40 страниц текстового слоя и до 10 сканированных страниц. Не все файлы имеют поддерживаемый извлекатель.
- Локальные правила не различают надёжно рекламу, новости, критику и учебные примеры. Упоминание термина не доказывает правонарушение; оценку инспектора нельзя подменять счётчиком слов.
- Текущий интерактив — подтверждения и два структурированных вопроса; свободного диалога и динамических вопросов от специализированных агентов пока нет.
- Официальные формы, юридический агент, статьи законов, поиск по всему интернету, обнаружение зеркал, государственные интеграции, электронная подпись и автоматическая блокировка **ещё не реализованы**.
- Контрольные суммы и журнал помогают сверять целостность, но не удостоверяют автора, время публикации или процессуальную допустимость. Администратор диска может изменить локальные данные. Время — часы сервера.
- Прерванное при перезапуске задание получает статус ошибки; полученные файлы сохраняются. Автоматического возобновления пока нет.

## Цели пилота

Проверить на 100–200 случаях сокращение работы со 120 до 15–30 минут. Бизнес-цели: 150 блокировок в месяц и 50–60 протоколов в год вместо 26. Это цели, а не подтверждённый эффект. Экспорт пакета не считается блокировкой или оформленным протоколом.

Следующая сессия начинается с [плана продолжения](docs/ROADMAP.md). Обзор открытых аналогов: [OPEN_SOURCE.md](docs/OPEN_SOURCE.md). Проект использует готовые библиотеки, но не является форком или интеграцией ArchiveBox/Browsertrix.

Запланированы три уровня продукта: **Базовый** без LLM, **AI-анализ** для углублённой проверки контекста и **Расследование** с агентом-детективом, агентом-юристом, специализированными проверками и поиском подтверждений в других публичных источниках. Режим «Расследование» пока существует только в плане.

## Три режима и расширение

Базовый режим не вызывает модель. Продвинутый выполняет три последовательных AI-этапа:
контекст, механика предложения и проверка выводов. Pro расширяет эту же цепочку:
юридический корпус и внешний поиск пока не подключены и явно отмечаются как пропуски.

Профили моделей и провайдеров задаются на сервере. Доступны OpenAI Responses и
Chat Completions-адаптер для LiteLLM Proxy или совместимого endpoint.
В инструкциях этапов нет прямых API-вызовов.
[Настройка, архитектура и тестовый прогон](docs/AI_GATEWAY.md).

Этапы сохраняют версии, наблюдения, противоречия, вопросы, модели и доступную статистику
токенов. Журнал доступен в интерфейсе, документах и inspection.json.
Три этапа не гарантируют точности: нужна проверка на независимых размеченных данных.
Реальные вызовы новой цепочки без API-ключа не проверялись.

Общая архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Базовые правила v2 и независимый пакет

Правила имеют стабильный ID и версию. Для каждого наблюдения сохраняются найденные
слова с точными позициями и локальные маркеры новостей, профилактики или учебного контекста.
Сочетания ищутся внутри одного абзаца на расстоянии до 240 символов. На правило
показываются максимум три совпадения в каждом уникальном тексте; это ограничение видно
в журнале. Одинаковые извлечённые тексты не считаются независимыми подтверждениями.
Контекстные маркеры требуют оценки инспектора, не доказывают отсутствие рекламы.
Вероятность и правовая квалификация в базовом режиме не вычисляются.

Сборка пакета вызывается отдельно после проверки. EvidencePackageService получает
версионированный снимок результатов, байты доказательств и шаблоны RU/KK.
Он не вызывает анализ, не обращается к SQLite и не меняет дело.
Форматирование (ReportLayout), DOCX, PDF и ZIP заменяются через интерфейсы.
Загрузка шаблона доступна в UI; регистрация новой логики оформления пока выполняется в коде.

В архиве формата aigak-evidence/2 case.json содержит снимок aigak-package-input/1,
а не весь объект очереди. template-source-ru.docx и template-source-kk.docx — точные
шаблоны, использованные для каждого языка; template-source.docx сохранён как RU-копия.
Отклонённые и неподтверждённые наблюдения не скрываются; их статусы сохраняются.
