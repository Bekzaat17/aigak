# aigak — план MVP

Основание: бриф и 7 слайдов презентации основателя. Казахстан, русский и казахский интерфейс. Локальный однопользовательский пилот, без автоматической отправки заявлений.

Уточнения пользователя: простой главный экран «ссылка / файл → Анализировать», оценка с доказательствами, встроенный и пользовательские DOCX-шаблоны, интерактивные вопросы и подтверждения инспектора. Расширение в набор специализированных skills/агентов и юридический модуль зафиксировано в [ROADMAP.md](ROADMAP.md), сейчас не реализуется.

## Сценарий

1. Офицер создаёт проверку из публичного URL, текста, PNG/JPEG/WebP, PDF, TXT или HTML; другие файлы сохраняются как оригиналы с явным сообщением об отсутствии извлечения.
2. Очередь фиксирует оригинал, время получения сервером, SHA-256, текст и происхождение производных материалов. Для URL — HTTP-ответ, цепочка редиректов и, при доступном браузере, скриншот и DOM.
3. Локальные правила обнаруживают признаки, RU/KK/EN; OCR работает локально после загрузки языковых моделей. Опциональный AI получает только материалы выбранного дела по явному выбору офицера. Каждая AI-цитата проверяется на наличие в сохранённом тексте.
4. Офицер принимает или отклоняет признаки, указывает своё имя и замечания. Отсутствие признаков не означает законность ресурса. Автоматических юридических квалификаций нет.
5. Экспорт ZIP: оригиналы, производные материалы, JSON дела, хэшированный журнал, manifest SHA-256, двуязычные HTML-отчёты для печати и проекты обращения. Пакет остаётся проектом, даже после внутренней проверки.

## Архитектура

React + TypeScript + Vite; Express + TypeScript; SQLite (node:sqlite); файловое хранилище. Playwright для снимков, Tesseract.js для локального OCR, PDF.js для PDF, JSZip для экспорта. Очередь последовательная; прерванные при перезапуске задания помечаются, оригиналы сохраняются. Только loopback-доступ в MVP.

## Критерии приёмки первой реализации

- Реальные загрузки и сохранение после перезапуска; нет искусственных показателей.
- Обработка ссылки, текста и изображения; на ошибке сбора — понятный статус и сохранённые материалы.
- Выводы привязаны к evidenceId и дословной цитате; новостной контекст требует проверки.
- Решения офицера и события сохраняются. Перед экспортом повторно проверяются хэши оригиналов.
- ZIP можно проверить независимо от приложения. Необнаруженный/непрочитанный материал не объявляется проверенным.
- RU/KK интерфейс, отчёты, поиск, фильтры, пример на явно синтетических данных.
- Тесты на SSRF, проверку цитат, целостность, переходы статусов и экспорт.

## Следующие этапы

1. Получить обезличенные принятые формы и возвраты от заказчика; верифицировать юридические основания и локализацию специалистом. Добавить утверждённые DOCX-шаблоны.
2. Интегрировать ArchiveBox или Browsertrix для WARC/WACZ, сложных страниц и повторного воспроизведения. Фиксировать версии сборщика и окружение.
3. Изолированный браузерный worker, PostgreSQL + объектное хранилище, аутентификация и роли, резервирование, внешний журнал и доверенное время.
4. Поиск связанных публичных страниц, группировка зеркал с объяснениями и подтверждением офицера. Никакого поиска частных лиц по изображениям.
5. Пилот на 100–200 случаях: медиана/P90 времени, доля принятых без доработки пакетов, ошибки извлечения, precision/recall, стоимость дела.

## KPI

Цель пилота: 15–30 минут вместо 120 минут на случай. Бизнес-цели: 150 подтверждённых блокировок/месяц и 50–60 протоколов/год вместо 26. Планка 500–650 из исходного брифа требует уточнения (команда или офицер). Сгенерированный пакет не считается блокировкой или протоколом; официальные результаты в MVP не измеряются.

## Границы доказательств

SHA-256 проверяет неизменность относительно сохранённого манифеста, но не удостоверяет реальное время публикации, автора, законность или юридическую допустимость. Локальный журнал не защищён от администратора с доступом к диску. Загрузка скриншота не доказывает доступность сайта по URL. Формы — проекты, не утверждённые процессуальные документы. OCR/AI требуют проверки человеком.
