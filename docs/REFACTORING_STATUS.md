## 14 октября 2026 — устойчивая очередь, Docker и ревью

Предыдущий пункт об очереди внутри API устарел: анализ теперь выполняется отдельным worker, задания и checkpoint сохраняются в PostgreSQL. Миграции вынесены в нумерованные файлы; добавлена `db:migrate`. `./scripts/up.sh` подготавливает и запускает весь стек, Chromium и OCR входят в сборку.

Ревью охватило границы server/application, инфраструктуру хранения/сети/очереди, AI-проверки, экспорт, HTTP, компоненты и hooks фронтенда, CSS и сценарии запуска. Исправлены смешение браузерной фиксации с сетевой политикой, смешение проверки пакета и его формирования, разные правила grounding цитат, дублирование проверки редактируемости дела и передачи HTTP-мутаций, монолит CSS. Ошибки PostgreSQL преобразуются на границе адаптера. У этапов обработки постоянные версионированные id, вместо зависимости checkpoint от позиции в массиве.

Проверки: обязательный `npm run check`, PostgreSQL integration с принудительным SIGKILL worker, UI smoke с отдельным worker. Проверка Docker выполняется на отдельном Compose project и синтетических данных; реальные материалы не отправляются внешним сервисам.

Осознанные ограничения: один worker на БД; at least once для незавершённого этапа; внешний AI может быть вызван повторно после аварии; файловая система и БД не составляют единую транзакцию. Это не обещание отсутствия всех возможных ошибок. Следующие изменения должны сохранять эти явные контракты либо расширять их с отдельными тестами.
