# Очередь и запуск Docker

## Одна команда

Установите и запустите Docker Desktop / Docker Engine с Compose. В корне проекта:

```sh
./scripts/up.sh
```

Node.js и Chrome на хосте для этого режима не нужны. Скрипт создаёт приватный `.env` со случайным паролем, только если файла ещё нет. Существующий `.env` не перезаписывается. Compose собирает образ, устанавливает Chromium и OCR-модели `rus/kaz/eng`, ждёт PostgreSQL, применяет миграции, готовит OCR-каталог и запускает API и worker. Первая сборка скачивает крупные зависимости; следующие используют Docker cache.

Интерфейс: http://localhost:4317 (либо `PORT` из `.env`). Публикация портов ограничена `127.0.0.1`, поскольку это локальное приложение без пользовательской аутентификации. Базовый анализ работает без AI-ключей. Для Продвинутого/Pro настройте AI в `.env` и повторите команду запуска. Автоматически получить ключ внешнего провайдера приложение не может.

## Сервисы и данные

- `postgres`: PostgreSQL 18, постоянный volume `postgres_data`.
- `migrate`: одноразовое применение нумерованных миграций.
- `assets`: копирует отсутствующие OCR-модели из образа в `DATA_DIR/ocr`, не заменяя имеющиеся.
- `api`: HTTP и интерфейс; сохраняет задания, не выполняет анализ.
- `worker`: отдельный процесс, последовательно исполняющий сохранённые задания.

API и worker используют один `DATA_DIR` (по умолчанию `./data`) для оригиналов и шаблонов. `DATABASE_URL` внутри контейнера указывает на сервис `postgres`; пароль передаётся отдельно через `PGPASSWORD`. Хостовый `DATABASE_URL` из `.env` остаётся пригоден для локальной разработки. `.env`, `data`, `.git` и результаты работы не попадают в образ.

```sh
docker compose logs -f api worker
docker compose ps
docker compose stop         # остановка без удаления данных
./scripts/up.sh              # сборка/обновление и запуск
```

Не используйте `docker compose down -v` для обычной остановки: он удаляет PostgreSQL volume. Резервная копия состоит из `pg_dump` и `DATA_DIR`; порядок описан в [POSTGRESQL.md](POSTGRESQL.md).

## Поведение очереди

HTTP подтверждает приём только после сохранения задания в `processing_jobs`. Обновление или закрытие страницы не влияет на обработку. Задания содержат состояние, число попыток и идентификаторы завершённых этапов. API при старте отдельно помечает незавершённый приём, для которого задание не было сохранено, чтобы такое дело не оставалось бесконечно «в очереди».

Worker получает эксклюзивную advisory lock на время своей работы. API имеет другую lock: один API и один worker могут работать одновременно, два worker — нет. Потеря соединения с lock останавливает процесс. Данная версия намеренно не поддерживает горизонтальное масштабирование worker.

После сохранения результатов этапа worker записывает его checkpoint. При перезапуске завершённые этапы пропускаются, незавершённый этап выполняется заново. Идентификаторы этапов версионированы; при изменении смысла этапа нужен новый id и продуманная совместимость незавершённых задач. Одна попытка ограничена watchdog в 30 минут (`PROCESSING_TIMEOUT_MS`); при превышении процесс завершается, чтобы Compose восстановил задание. После трёх попыток восстановления дело переводится в ошибку. Ошибка обычного анализа сохраняет частичные материалы и завершается без бесконечных повторов.

Гарантия выполнения — **at least once для незавершённого этапа**, не exactly once для внешнего API. Сбой между внешним запросом и checkpoint может повторить запрос, расход AI или сбор материала. Уже сохранённые оригиналы не перезаписываются. PostgreSQL и файловая система не имеют общей транзакции; оборванный приём или конфликт могут оставить файл без записи в каталоге. Автоматическое удаление таких файлов не выполняется.

При SIGTERM worker завершает текущую задачу; Docker ждёт 30 секунд, затем может остановить его принудительно. Следующий запуск восстанавливает задание. Состояние API проверяется HTTP healthcheck; worker обновляет временный heartbeat независимо от каталога материалов.

## Разработка без контейнера приложения

```sh
npm ci
npm run db:up
npm run db:migrate
npm run setup:ocr
npm run dev
# В другом терминале:
npm run worker
```

Для Playwright нужен Chrome (`BROWSER_CHANNEL=chrome`) либо установленный Chromium. Не запускайте хостовый API/worker одновременно с их Docker-экземплярами на той же БД: эксклюзивные lock отклонят второй процесс.

## Проверки

`npm run check` проверяет стиль, границы архитектуры, unit/HTTP-тесты и production-сборку. `TEST_DATABASE_URL=... npm run test:postgres` создаёт отдельную схему и проверяет миграции, взаимное исключение worker, checkpoint, очередь и восстановление после настоящего `SIGKILL` дочернего процесса. `SMOKE_DATABASE_URL=... npm run test:ui` запускает отдельные API/worker на синтетических данных, проверяет сценарии UI и удаляет временную схему.
