# Сценарии и агенты Aigak Pro

Решение по запросу владельца от 15.10.2026. Цель: инспектор выбирает URL и
разрешённый сценарий. Система выполняет проверку, сохраняет доказательства и историю.
Это целевая архитектура; текущие ограничения перечислены в конце.

## Ответственность

| Роль                 | Задача                                                                                                                | Результат                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Оркестратор          | Запустить граф сценария, выдать ограниченные полномочия, учитывать бюджет, выбрать запасной путь, сохранить состояние | История переходов и итоговый статус                    |
| Сборщики             | HTTP, браузер с JS, независимый сетевой браузер, OCR                                                                  | Материалы с URL, временем, способом получения          |
| Агент доступа        | Вход, разрешённая регистрация, подтверждение почты                                                                    | Подтверждённая сессия или конкретное ограничение       |
| Аналитик содержимого | Найти признаки в полученных материалах                                                                                | Гипотезы с точными цитатами и ID источников            |
| Агент связей         | Найти связанные домены, соцсети и компанию                                                                            | Связи с доказательствами, отдельно от исходного сайта  |
| Правовой аналитик    | Сопоставить факты с нормами и лицензией                                                                               | Название акта, статья, ссылка, применимость и пробелы  |
| Независимая проверка | Проверить качество сбора, цитаты, снимки, доступ и юридические ссылки                                                 | Принять, вернуть на конкретную доработку или отклонить |
| Составление отчёта   | Представить принятые выводы без новых фактов                                                                          | Краткий отчёт и подробная история                      |

Роль не обязана быть отдельным LLM-вызовом или микросервисом. Проверка хеша,
точной цитаты, домена и разрешённого действия выполняется кодом. Каждый AI-анализ
имеет отдельный версионированный промпт, схему ответа и учёт расходов.
Одинаковая модель в нескольких ролях не означает независимости доказательств.

## Управление процессом

Один оркестратор владеет состоянием дела. Агенты получают только необходимые
порты и неизменяемые входные материалы, возвращают структурированные результаты.
Параллельные задачи не пишут напрямую в общий CaseRecord; оркестратор применяет
результаты последовательно и сохраняет ссылки на первичные материалы.

Публичные способы сбора допускают ограниченный параллелизм. Вход и регистрация
исполняются последовательно в одной сессии; повтор после таймаута не должен
создавать второй аккаунт. Сессия не передаётся в промпты и журнал.

Проверяющий не редактирует доказательства и не утверждает собственные выводы.
Он возвращает структурированный дефект и нужный тип повторной работы. Оркестратор
выбирает только из зарегистрированных разрешённых переходов. Ответ модели не
может расширить разрешения, бюджет или перечень доменов.

У каждого узла есть предусловия, критерий успеха, таймаут, лимит попыток и
запасной переход. Общий бюджет целевой проверки — 400 секунд, включая финальную
сверку. Пример распределения: 220 секунд на получение доступа и материалов,
120 на анализ, 60 на финальную проверку. Это план, а не текущая гарантия времени.
Одинаковая неудача не повторяется без изменения условий. Исчерпание бюджета
даёт частичный отчёт с сохранёнными доказательствами, а не фиктивный успех.

## Условия выпуска результата

- Отсутствие доступа не превращается в «признаков нет» или вероятность 0%.
- Находка ссылается на существующий источник и точный диапазон цитаты.
- Снимок показывает эту цитату; перед и после снимка сверяются видимость и положение.
- Для закрытого источника повторно подтверждается авторизация перед снимком.
- Юридический вывод содержит акт, статью, официальный URL и основания применимости.
- Противоречия сохраняются; вероятности разных агентов не усредняются автоматически.
- Отчёт не добавляет фактов, которых нет в принятых результатах.
- История хранит попытки, причины переходов, версии, длительность, фактические
  токены и расходы. Неизвестная стоимость обозначается как неизвестная, не как ноль.

## Библиотеки и границы

Stagehand — кандидат на адаптер семантических действий браузера; Crawlee — на
управление массовым сбором. Они подключаются через порты в bootstrap и не владеют
решением о достоверности, юридическим выводом или историей дела. Browser Use —
альтернатива, если потребуется отдельный Python-процесс. Ссылки и ограничения —
в [COLLECTION.md](COLLECTION.md).

## Текущая реализация и следующие изменения

Уже есть `CaseProcessingService`, отдельные ProcessingStage, зарегистрированные
InspectionCheck/InspectionStrategy, независимая проверка точных цитат и снимков.
Сборщики работают через UrlCollectionMethod; оценка их результата вынесена в
заменяемый CollectionReviewer. Сборщик не назначает своему результату статус успеха.
Вход/регистрация по настроенному профилю и тестовому почтовому адаптеру проверены
браузерными тестами. Повторная проверка приватной находки требует действующей сессии.

Ещё не реализованы: универсальное понимание формы через Stagehand, создание
реального ящика, возобновление после CAPTCHA/2FA, общий 400-секундный бюджет,
граф повторной доработки по заключению проверяющего и параллельный сбор с
изолированными результатами. Текущие 300 секунд относятся только к сбору.
Их нужно внедрять поведенческими вертикальными сценариями, а не пустыми классами
агентов. Первый сценарий приёмки: публичный сбор → выявленный вход → разрешённая
регистрация → письмо → закрытая страница → находка → независимая проверка → отчёт.
