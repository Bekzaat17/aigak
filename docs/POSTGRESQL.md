# PostgreSQL

PostgreSQL 18 хранит дела и каталог шаблонов. Оригиналы, DOCX и OCR-модели остаются в `DATA_DIR`. Схема данных дела и контрольные суммы не меняются.

Для автоматического запуска всех сервисов используйте `./scripts/up.sh`: [очередь и Docker](QUEUE_AND_DOCKER.md). Ниже — ручной режим разработки.

## Новый запуск

1. Установите Docker с Compose, Node.js 22.13+ и зависимости через `npm ci`.
2. Скопируйте `.env.example` в `.env`. Задайте приватный `POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`. Символы пароля в URL должны быть percent-encoded; случайная hex-строка не требует кодирования.
3. `npm run db:up` поднимает PostgreSQL на `127.0.0.1:5432`. Volume `postgres_data` сохраняется между перезапусками.
4. `npm run dev` или `npm run build && npm start` запускает приложение. Схема создаётся автоматически под транзакционной блокировкой. Анализ исполняет отдельный `npm run worker` в другом терминале.

Для внешнего PostgreSQL задайте `DATABASE_URL` с необходимыми TLS-параметрами и не запускайте Compose. Приложение не отключает проверку сертификата. Нужны права создания таблиц, индексов и sequence в целевой схеме. Не публикуйте `.env` и дампы базы в Git.

## Перенос существующей SQLite

Остановите API и worker и убедитесь, что исходная SQLite больше не изменяется. Сохраните резервную копию всего `DATA_DIR`, включая SQLite и её WAL-файлы, если они остались. Целевая PostgreSQL должна быть пустой.

```bash
npm run db:up
npm run db:import -- /absolute/path/to/data/aigak.sqlite
npm run dev
```

Импорт открывает SQLite только для чтения, проверяет цепочки аудита, ревизии, файлы доказательств и шаблоны. Вставки выполняются одной транзакцией. Исходный JSON копируется без переформатирования. Файлы не копируются и не удаляются: `DATA_DIR` после перехода должен указывать на прежний каталог. При переносе на другой компьютер перенесите весь каталог отдельно.

Повторный импорт идентичной базы возвращает `alreadyImported: true`. Если в PostgreSQL данные уже изменились, импорт прекращается с `MIGRATION_TARGET_NOT_EMPTY`. Он не выполняет слияние и не перезаписывает новые записи. Запущенный API или worker блокирует импорт (`DATABASE_IN_USE`).

## Устройство и ограничения

- Асинхронные репозитории подключены через порты; SQLite оставлена как тестовый/совместимый адаптер. Для явного прежнего режима используется `STORAGE_DRIVER=sqlite`, автоматического fallback нет.
- Поле дела — `text` с JSON-проверкой. Здесь намеренно не используется `jsonb`: сохранённый порядок ключей участвует в прежнем алгоритме хеширования. Это соответствует различиям типов в [документации PostgreSQL](https://www.postgresql.org/docs/current/datatype-json.html).
- Номера дел выделяет PostgreSQL sequence; пропуски после ошибки допустимы, номера не переиспользуются.
- Устаревшее обновление получает HTTP 409 `CASE_CONFLICT`. Откройте дело заново перед повторной правкой.
- Поддерживаются один API и один worker на базу. Раздельные advisory lock отклоняют дублирующие экземпляры. Потеря соединения, удерживающего lock, останавливает процесс.
- Браузер не удерживает запрос анализа: приём возвращает дело, дальше идёт опрос статуса. Очередь сохраняется в PostgreSQL; отдельный worker восстанавливает незавершённые задачи по checkpoint.
- Файловая система и БД не образуют общую транзакцию. Не удаляйте `DATA_DIR` после миграции.

## Резервные копии и откат

Для согласованной копии остановите API и worker, сделайте `pg_dump` и скопируйте `DATA_DIR` в защищённое место. Для восстановления нужны обе части. Пароль передавайте через защищённое окружение или `.pgpass`, не включайте его в команды, сохраняемые в shell history.

Старая SQLite остаётся снимком до миграции. Переключение на неё **не переносит обратно** изменения из PostgreSQL. Для отката после новых изменений требуется отдельный экспорт; не переключайте драйвер с ожиданием автоматической синхронизации.

`docker compose stop postgres` сохраняет volume. `docker compose down -v` удаляет данные PostgreSQL — не используйте эту команду для обычной остановки.

## Проверки

```bash
npm run check
TEST_DATABASE_URL=postgres://... npm run test:postgres
SMOKE_DATABASE_URL=postgres://... npm run test:ui
```

Интеграционный тест создаёт отдельную схему и удаляет только её. Проверяет отказ при нарушении целостности, неизменность исходной SQLite, повторный импорт, перезапуск, конфликт записей и номера дел. Браузерный сценарий с `SMOKE_DATABASE_URL` запускайте только на отдельной тестовой базе: он создаёт синтетические дела в отдельной временной схеме, затем удаляет эту схему и временные файлы. Без переменной сценарий использует временную SQLite.
