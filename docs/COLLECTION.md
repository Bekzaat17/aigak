# Сбор и подтверждение страниц

MVP запускает новые проверки по ссылке. Старые дела и API импорта сохранены
для совместимости. Основная архитектура — [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md).

В Pro HTTP и Chromium запускаются параллельно с изолированными результатами.
Недостаточный результат вызывает запасную волну: другой сетевой способ и мобильный
размер экрана. Затем браузерный агент может пройти по информационным ссылкам.
Ошибка одного сборщика не отменяет остальные. При недостаточном сборе нет вывода
об отсутствии признаков и нет выдуманного процента.

Native Chromium использует собственный TLS через CONNECT-прокси с проверкой и
закреплением публичного DNS. Этот способ независим от Node HTTP, но не меняет
внешний IP и не гарантирует доступ при сетевой блокировке.

## Доступ после авторизации

Инспектор выбирает публичный анализ, вход по подготовленному профилю либо
автоматическую регистрацию с временной почтой. Автоматический сценарий поддерживает
email/password и использует [Mail.tm](https://mail.tm). Персональные данные не
выдумываются; CAPTCHA не обходится. Одноразовый код можно ввести в открытом деле,
пока агент ожидает его в той же сессии.

Администратор задаёт подготовленные профили в `AIGAK_AUTH_PROFILES` (JSON-массив).
Профиль содержит `id`, `name`, `origin`, `registration`, `login`, необязательный
`register`, `successSelector`, `readUrls`. Форма: `url`, `fields` (селектор →
значение), `submitSelector`, `submitUrls`, необязательные `fieldHints` (селектор →
описание поля). Все страницы и POST принадлежат разрешённому HTTPS origin.
Пароли не выдаются через API каталога профилей.

Необязательный `verification` содержит `endpoint`, `token`, `allowedPathPrefix`.
Доверенный почтовый адаптер возвращает `{ "verificationUrl": "https://…" }`;
ссылка проверяется по домену и пути. В автоматическом сценарии MailTmInbox хранит
свои учётные данные только в памяти и удаляет ящик при нормальном завершении.

Вход подтверждается видимым признаком сессии. До четырёх настроенных внутренних
страниц проверяются повторно. Материалы помечаются «после входа» в UI и экспорте;
контекст сохраняется до проверки цитат. Повторная регистрация того же дела
запрещена, в том числе после перезапуска.

Stagehand 4.2.1 получает только копию видимых элементов без введённых значений.
`BROWSER_AGENT_MODEL` задаёт модель (по умолчанию OPENAI_MODEL либо системная),
`STAGEHAND_CHROME_PATH` — необязательный путь к Chromium. Фактические токены
SDK сохраняются в истории; цена без тарифа не вычисляется.

## Доказательства и история

EvidenceSupervisor перепроверяет точную цитату и пробует другой браузерный способ
при отсутствии снимка. BrowserFindingVerifier проверяет видимость, положение
до/после захвата и авторизацию закрытого источника. Общий снимок страницы не
подменяет снимок находки. Это DOM-проверка, не независимая экспертиза изображения.

`refreshSources: true` создаёт ревизию и обновляет сбор. Оригиналы и предыдущий
результат сохраняются. История содержит способы, решения, длительность, материалы,
расход токенов и ограничения. Общий дедлайн Pro — 400 секунд; отменённая стадия
не вправе позднее перезаписать результат.

Оценка содержимого отделена от юридической применимости. Процент является
некалиброванной оценкой наличия игорного предложения, не вероятностью незаконности.
Для правовой гипотезы обязательны точные нормы, статьи и источники.

Проверки: `npm run check`,
`node --import tsx --test tests/authentication.integration.ts tests/browser-collection.integration.ts`,
`BROWSER_CHANNEL=chrome node scripts/smoke-ui.mjs`.
Тестовые материалы синтетические; реальные прогоны создаются отдельно через API.
